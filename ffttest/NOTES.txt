FFT for 68000 - Implementation Notes
=====================================

PURPOSE
-------
Transform 16-bit signed mono PCM audio to frequency domain and back.
Useful for: spectral analysis, filtering, pitch detection, compression, effects.


FILES
-----
fft_68k.h   - Public API header
fft_68k.c   - Implementation
fft_test.c  - Test program (round-trip verification)
Makefile    - Build for Linux test or Amiga cross-compile


ALGORITHM
---------
Radix-2 Cooley-Tukey Decimation-In-Time FFT

Complexity: O(N log N) vs O(N²) for naive DFT
For N=256: ~2048 butterflies vs 65536 complex multiplies

Each "butterfly" operation:
  temp = W * odd
  even' = even + temp
  odd'  = even - temp

Where W = twiddle factor = e^(-j*2*pi*k/N) = cos() - j*sin()


FIXED-POINT FORMAT
------------------
Q15: 16-bit signed, implicit /32768 scaling
Range: -1.0 to +0.99997
Multiplication: (a * b) >> 15 with rounding

68000 MULS instruction: 16x16->32 in ~70 cycles
Shift/add: 4-8 cycles

The implementation minimizes multiplications by:
- Precomputed twiddle factors (sin/cos lookup table)
- Precomputed bit-reversal permutation


SCALING STRATEGY
----------------
To prevent overflow in 16-bit arithmetic:

Forward FFT:
  - No input scaling
  - Scale by 1/2 at each butterfly (total: 1/N)

Inverse FFT:
  - Scale by 1/2 at each butterfly (total: 1/N)
  - Scale output by N (shift left by log2(N))

This ensures values stay within 16-bit range throughout.


FFT SIZE
--------
Currently: 256 samples (FFT_SIZE_LOG2 = 8)

Trade-offs:
- Larger FFT = better frequency resolution, more CPU, more memory
- Smaller FFT = faster, less latency, coarser frequency bins

For 256-point at 22050 Hz sample rate:
- Frequency resolution: 22050/256 = 86 Hz per bin
- Time window: 256/22050 = 11.6 ms

To change size: modify FFT_SIZE and FFT_SIZE_LOG2 in header,
and expand sin_quarter[] table if needed.


MEMORY USAGE
------------
Tables (allocated once at init):
- sin_table:    512 bytes (256 shorts)
- window_table: 512 bytes (256 shorts)
- bit_reverse:  512 bytes (256 unsigned shorts)
Total: ~1.5 KB

Working data:
- Complex16 arrays: 1 KB each (256 * 4 bytes)
- Static work buffer in fft_inverse: 1 KB

Total per transform: ~2.5 KB


CPU COST (68000 ESTIMATE)
-------------------------
Per butterfly: ~4 multiplications + ~10 adds/shifts
68000 MULS: ~70 cycles, ADD/ASR: ~8 cycles

For 256-point FFT: 256*8/2 = 1024 butterflies
Estimated: 1024 * (4*70 + 10*8) = ~370K cycles

At 7 MHz: ~53 ms per 256-sample block
At 14 MHz: ~26 ms per 256-sample block

For real-time at 22050 Hz: need to process 256 samples in 11.6 ms
Marginal on stock 68000, comfortable on 68020+


USAGE PATTERN FOR STREAMING
---------------------------
For continuous audio processing, use overlap-add:

1. Collect 256 samples
2. Apply window (fft_apply_window) - reduces spectral leakage
3. Forward FFT
4. Process frequency bins (filter, analyze, modify)
5. Inverse FFT
6. Overlap-add with previous block (50% overlap typical)
7. Output 128 samples

Window function (Hanning) prevents discontinuities at block edges.

-----------

POTENTIAL OPTIMIZATIONS
-----------------------
1. Assembly inner loop for butterfly
   - Unroll, use address registers efficiently
   - 68020+ can use MULU.L for 32-bit results

2. Radix-4 FFT reduces butterfly count by ~25%
   - More complex code, same memory

3. Real-only FFT (pack two real transforms)
   - Halves computation for real signals
   - Requires unpacking logic

4. Split-radix FFT
   - Lowest known multiply count
   - Complex implementation


ACCURACY
--------
Test shows average error ~56 per sample on 16-bit signal.
This is ~0.17% error, acceptable for audio.

Main error sources:
- Q15 multiplication rounding
- Sine table quantization (16-bit)

For better accuracy: use 32-bit intermediates (slower on 68000).


FREQUENCY BIN INTERPRETATION
----------------------------
For N-point FFT of real signal:
- Bin 0: DC component
- Bin 1 to N/2-1: positive frequencies
- Bin N/2: Nyquist frequency
- Bin N/2+1 to N-1: negative frequencies (mirror of positive)

Frequency of bin k: f = k * sample_rate / N

For 256-point at 22050 Hz:
- Bin 1 = 86 Hz
- Bin 10 = 860 Hz
- Bin 100 = 8.6 kHz
- Bin 128 = 11025 Hz (Nyquist)
